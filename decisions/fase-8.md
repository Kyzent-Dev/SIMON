# Keputusan Fase 8

## Fase 8, Task 1
- `App\Services\Triwulan` membaca `rekap.dasar_triwulan` sekali per instance (tidak di-singleton-kan, jadi perubahan pengaturan berlaku pada resolusi berikutnya). Dasar `tanggal_lhp` jatuh ke `tanggal_selesai` bila `tanggal_lhp` kosong; SPT tanpa tanggal dasar tidak masuk rekap.
- Tanggal dasar item PKPT = rentang efektif `KesesuaianPkpt::rentang()` (revisi disetujui terakhir dulu): tanggal selesainya, atau tanggal mulainya bila pengaturan `tanggal_mulai`. Item tidak punya LHP, jadi `tanggal_lhp` memakai tanggal selesai item.
- Tahun dan TW rekap ditentukan oleh tanggal dasar (kolom `spt.tahun` tidak dipakai untuk rekap); filter Tahun monitoring dan dasbor memakai `spt.tahun`. Filter `tw` monitoring = tanggal dasar di dalam `Triwulan::rentang(tahun filter, tw)`, digabung dengan `spt.tahun = tahun filter`.
- `Triwulan::batasi(Builder, tahun, ?tw)` adalah kembaran SQL `tanggalDasar()` (pakai `whereDate`, karena SQLite menyimpan kolom tanggal sebagai `Y-m-d H:i:s`); rekap tetap memeriksa ulang tahun lewat `tanggalDasar()` di PHP.
- Rencana hanya dari PKPT tahun itu berstatus Disahkan; `target_spt` null dihitung 1 (satu item merencanakan minimal satu SPT). Tanpa PKPT Disahkan rencana 0, `persen` null, dan `pkpt_disahkan = false` (halaman menampilkan alert). Item yang tanggal dasarnya jatuh di tahun lain (mis. revisi ke tahun berikutnya) tidak dihitung pada tahun itu.
- Realisasi per irban memakai `spt.irban_id` (bukan irban item). Baris rekap: semua irban urut id (atau satu irban saat dibatasi), semua klasifikasi urut id, semua jenis penugasan urut nama, termasuk baris bernilai nol; ditambah baris `Tanpa jenis penugasan` (id null) hanya bila ada SPT tercatat manual tanpa jenis.
- Bentuk keluaran `RekapTriwulan::hitung()`: tiga tabel `irban`/`klasifikasi`/`jenis`, masing-masing `{baris: [...], total: {tw, total}}`; `irban.total` adalah tabel Gabungan. `persen` di baris total dihitung ulang dari jumlah, tidak dirata-rata.
- Penanda di monitoring dihitung di PHP dalam satu batch per set tahun (`PenandaSpt::untukBanyak()`), tanpa scope SQL untuk penanda. `untukBanyak` memuat `pkptItem.revisiDisetujui` (relasi baru, urut `diputuskan_pada` lalu id) dan `withExists` dokumen final (`final_ada`); `untuk()` dan `KesesuaianPkpt::rentang()` memakai data yang sudah dimuat bila ada, jadi aturannya tetap satu. Terukur: `untukBanyak` 3 query untuk 5 maupun 50 SPT; `MonitoringSpt::baris()` 9 query (SQLite tes) untuk 6 maupun 1.000 SPT (±1,1 detik di mesin dev, tes tanpa opcache); data demo 13 query / 9 ms (termasuk baca cache pengaturan), rekap demo 8 query / 7 ms.
- `MonitoringSpt::filter()` memvalidasi semua filter (nilai tak dikenal kembali ke bawaan: tahun = tahun berjalan Jakarta, dibatasi 2000–2100; lainnya null); `irban`/`jenis` harus id yang ada. Status `berjalan` = diterima dan belum ditandai selesai (seluruh kelompok On Process). Hanya grup item yang punya baris SPT yang tampil; grup `Di luar PKPT` selalu terakhir. SPT dalam grup urut `tanggal_mulai` lalu id.
- Kesesuaian baris: tanpa item = `non_pkpt`; penanda `tidak_sesuai_pkpt` = `tidak_sesuai`; selain itu `sesuai` (termasuk SPT beritem yang tanggalnya belum lengkap, karena penandanya tidak dinilai).
- Tes status: baris matriks untuk SPT Dibatalkan dengan `ditandai_selesai_pada` lama (status Dibatalkan, `berstatus(Selesai)` tidak memuatnya) ditambahkan; perilaku sudah benar sebelumnya.

## Fase 8, Task 2
- Jalur ekspor tunggal `App\Services\Ekspor::minta()`; tiap jenis tabel adalah satu kelas `App\Services\Ekspor\Pembangun` (otorisasi, `filter()` yang memvalidasi dan membatasi per pengguna, `jumlah()`, `namaFile()`, `export()` berupa `ArrayExport`, `html()` untuk dompdf, `halaman()`). Monitoring dan Rekap cukup mendaftarkan satu kelas di `Ekspor::PEMBANGUN`. Jalur langsung dan job memakai pembangun yang sama.
- `BuatEkspor` memanggil `Ekspor::tulis()`, yang memeriksa ulang otorisasi pengguna tersimpan dan memvalidasi ulang filter; kegagalan apa pun (termasuk otorisasi) menandai `gagal` dan mengirim `EksporGagal` (job tidak dilempar ulang, `tries = 1`).
- File ditulis ke disk `local` (`storage/app/private/ekspor/{uuid}.{format}`). Unduh lewat `EksporController` (pemilik, status `selesai`, file ada; selain itu 404). `ekspor:bersihkan` (05.00 Asia/Jakarta) menghapus baris dan file yang `created_at`-nya lebih dari 7 hari.
- Penerima `EksporSiap`/`EksporGagal` diambil dari `PenerimaNotifikasi::pengguna(User)`. Tombol email `Unduh` lewat metode `NotifikasiSimon::labelTombol()` yang bisa ditimpa.
- Register (`ekspor()`) memakai jalur ini; perilaku <= 1000 baris tidak berubah. Tes memakai pembangun palsu (`jumlah()` ditimpa) untuk menguji batas 1000 tanpa membuat 1001 SPT.
