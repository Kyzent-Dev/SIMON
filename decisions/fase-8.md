# Keputusan Fase 8

## Fase 8, Task 1
- `App\Services\Triwulan` membaca `rekap.dasar_triwulan` sekali per instance (tidak di-singleton-kan, jadi perubahan pengaturan berlaku pada resolusi berikutnya). Dasar `tanggal_lhp` jatuh ke `tanggal_selesai` bila `tanggal_lhp` kosong; SPT tanpa tanggal dasar tidak masuk rekap.
- Tanggal dasar item PKPT = rentang efektif `KesesuaianPkpt::rentang()` (revisi disetujui terakhir dulu): tanggal selesainya, atau tanggal mulainya bila pengaturan `tanggal_mulai`. Item tidak punya LHP, jadi `tanggal_lhp` memakai tanggal selesai item.
- Tahun dan TW rekap ditentukan oleh tanggal dasar (kolom `spt.tahun` tidak dipakai untuk rekap); filter Tahun monitoring dan dasbor memakai `spt.tahun`. Filter `tw` monitoring = tanggal dasar di dalam `Triwulan::rentang(tahun filter, tw)`, digabung dengan `spt.tahun = tahun filter`.
- `Triwulan::batasi(Builder, tahun, ?tw)` adalah kembaran SQL `tanggalDasar()` (pakai `whereDate`, karena SQLite menyimpan kolom tanggal sebagai `Y-m-d H:i:s`); rekap tetap memeriksa ulang tahun lewat `tanggalDasar()` di PHP.
- Rencana hanya dari PKPT tahun itu berstatus Disahkan; `target_spt` null dihitung 1 (satu item merencanakan minimal satu SPT). Tanpa PKPT Disahkan rencana 0, `persen` null, dan `pkpt_disahkan = false` (halaman menampilkan alert). Item yang tanggal dasarnya jatuh di tahun lain (mis. revisi ke tahun berikutnya) tidak dihitung pada tahun itu.
- Realisasi per irban memakai `spt.irban_id` (bukan irban item). Baris rekap: semua irban urut id (atau satu irban saat dibatasi), semua klasifikasi urut id, semua jenis penugasan urut nama, termasuk baris bernilai nol; ditambah baris `Tanpa jenis penugasan` (id null) hanya bila ada SPT tercatat manual tanpa jenis.
- Bentuk keluaran `RekapTriwulan::hitung()`: tiga tabel `irban`/`klasifikasi`/`jenis`, masing-masing `{baris: [...], total: {tw, total}}`; `irban.total` adalah tabel Gabungan. `persen` di baris total dihitung ulang dari jumlah, tidak dirata-rata.
- Penanda di monitoring dihitung di PHP dalam satu batch per set tahun (`PenandaSpt::untukBanyak()`), tanpa scope SQL untuk penanda. `untukBanyak` memuat `pkptItem.revisiDisetujui` (relasi baru, urut `diputuskan_pada` lalu id) dan `withExists` dokumen final (`final_ada`); `untuk()` dan `KesesuaianPkpt::rentang()` memakai data yang sudah dimuat bila ada, jadi aturannya tetap satu. Terukur: `untukBanyak` 3 query untuk 5 maupun 50 SPT; `MonitoringSpt::baris()` 9 query (SQLite tes) untuk 6 maupun 1.000 SPT (±1,1 detik di mesin dev, tes tanpa opcache); data demo 13 query / 9 ms (termasuk baca cache pengaturan), rekap demo 8 query / 7 ms.
- `MonitoringSpt::filter()` memvalidasi semua filter (nilai tak dikenal kembali ke bawaan: tahun = tahun berjalan Jakarta, dibatasi 2000–2100; lainnya null); `irban`/`jenis` harus id yang ada. Status `berjalan` = diterima dan belum ditandai selesai (seluruh kelompok On Process). Hanya grup item yang punya baris SPT yang tampil; grup `Di luar PKPT` selalu terakhir. SPT dalam grup urut `tanggal_mulai` lalu id.
- Kesesuaian baris: tanpa item = `non_pkpt`; penanda `tidak_sesuai_pkpt` = `tidak_sesuai`; selain itu `sesuai` (termasuk SPT beritem yang tanggalnya belum lengkap, karena penandanya tidak dinilai).
- Tes status: baris matriks untuk SPT Dibatalkan dengan `ditandai_selesai_pada` lama (status Dibatalkan, `berstatus(Selesai)` tidak memuatnya) ditambahkan; perilaku sudah benar sebelumnya.

## Fase 8, Task 2
- Jalur ekspor tunggal `App\Services\Ekspor::minta()`; tiap jenis tabel adalah satu kelas `App\Services\Ekspor\Pembangun` (otorisasi, `filter()` yang memvalidasi dan membatasi per pengguna, `jumlah()`, `namaFile()`, `export()` berupa `ArrayExport`, `html()` untuk dompdf, `halaman()`). Monitoring dan Rekap cukup mendaftarkan satu kelas di `Ekspor::PEMBANGUN`. Jalur langsung dan job memakai pembangun yang sama.
- `BuatEkspor` memanggil `Ekspor::tulis()`, yang memeriksa ulang otorisasi pengguna tersimpan dan memvalidasi ulang filter; kegagalan apa pun (termasuk otorisasi) menandai `gagal` dan mengirim `EksporGagal` (job tidak dilempar ulang, `tries = 1`).
- File ditulis ke disk `local` (`storage/app/private/ekspor/{uuid}.{format}`). Unduh lewat `EksporController` (pemilik, status `selesai`, file ada; selain itu 404). `ekspor:bersihkan` (05.00 Asia/Jakarta) menghapus baris dan file yang `created_at`-nya lebih dari 7 hari.
- Penerima `EksporSiap`/`EksporGagal` diambil dari `PenerimaNotifikasi::pengguna(User)`. Tombol email `Unduh` lewat metode `NotifikasiSimon::labelTombol()` yang bisa ditimpa.
- Register (`ekspor()`) memakai jalur ini; perilaku <= 1000 baris tidak berubah. Tes memakai pembangun palsu (`jumlah()` ditimpa) untuk menguji batas 1000 tanpa membuat 1001 SPT.
- `BuatEkspor::failed()` (dipanggil antrean saat time-out/dibunuh, dan oleh `handle()` saat pengecualian) menandai `gagal` hanya bila status masih `menunggu`, mengirim `EksporGagal` sekali, dan menghapus file `ekspor/{id}.{format}` yang setengah jadi. Bawaan `retry_after` antrean database dinaikkan dari 90 ke 660 detik (`DB_QUEUE_RETRY_AFTER`), lebih besar dari `timeout` job (600), agar job panjang tidak dipesan ulang; catatan deploy ada di Task 6.

## Fase 8, Task 3
- Halaman `App\Livewire\Pimpinan\Monitoring` (`/pimpinan/monitoring`, `pimpinan.monitoring`, menu `Monitoring SPT` ikon `table-cells` sebelum `Revisi Jadwal`). Otorisasi lewat `SptPolicy::monitoring` (Pimpinan saja) di `mount()`, `updated()`, `aturUlang()`, `ekspor()` dan `render()`; pembangun ekspor memakai gate yang sama.
- Filter URL disimpan sebagai string dan divalidasi ulang lewat `MonitoringSpt::filter()` pada setiap render; hasilnya ditulis balik ke properti, jadi nilai URL yang tidak dikenal kembali ke bawaan dan select menampilkan bawaan. Halaman grup di luar jangkauan dijepit ke halaman terakhir.
- Paginasi 20 grup per halaman memakai `LengthAwarePaginator` atas hasil `MonitoringSpt::baris()` (seluruh tahun dihitung lalu diiris; sesuai pengukuran Task 1). Teks `Menampilkan 1–20 dari N` pada `x-ui.pagination` menghitung grup, bukan SPT.
- `x-ui.table` mendapat prop `grouped`: slot memberi `<tbody>` sendiri (satu per grup, baris grup `<th scope="rowgroup" colspan="6">`). Status buka/tutup grup di Alpine per grup (`buka`), `Buka semua`/`Tutup semua` lewat event window `monitoring-grup`; `wire:key` grup memuat hash filter sehingga keadaan bawaan dipasang ulang saat filter berubah. Tanpa animasi.
- Baris SPT: kolom pertama memuat nomor SPT (tautan detail) + keterangan `{jenis} · {irban}`; kolom Periode PKPT mengulang periode efektif grup (`–` untuk Di luar PKPT). Status menampilkan badge + flag Terlambat saja (flag `SPT Final Belum Diupload` tidak ditampilkan di tabel ini, sesuai pimpinan.md). Tombol `Selengkapnya` hanya muncul bila kategori + uraian kendala > 70 karakter (heuristik server; clamp 2 baris tetap berlaku).
- Filter seluler memakai `x-ui.drawer` yang ada (masuk dari kanan, ukuran sm), bukan bottom sheet DESIGN §11; isinya partial yang sama dengan bar filter desktop (id berawalan `f-`/`d-`). Chip `Terlambat`/`Permintaan Penjelasan Terbuka` hanya untuk `penanda`/`penjelasan` (diset dari kartu dasbor), dengan tombol `Hapus filter …`.
- Pada 1280 dengan sidebar terbuka tabel lebih lebar dari kontainernya (1079 vs 950 px, data demo dengan kendala): kolom `Permasalahan/Kendala` digulir di dalam kontainer `overflow-x-auto` (kolom pertama sticky, petunjuk tepi kanan); tidak ada gulir horizontal halaman. Pada 1536 tabel muat.
- `PembangunMonitoring`: kolom `Nomor SPT, Irban, Jenis Penugasan, Periode Penugasan (PKPT), Realisasi Periode, Kesesuaian dengan Jadwal PKPT, Status, Permasalahan/Kendala`; Jenis Penugasan = label grup (`Di luar PKPT` untuk non-PKPT); Status = label + `, Terlambat` bila terlambat; Kendala = `{kategori}: {uraian}`; kolom A diformat teks. `jumlah()` menghitung baris dari `MonitoringSpt::baris()`. Label status/kesesuaian/TW untuk halaman dan ringkasan filter PDF ada sebagai konstanta di pembangun ini.

## Fase 8, Task 4
- Satu komponen `App\Livewire\Rekap` melayani `pimpinan.rekap` (judul `Rekap Triwulanan`) dan `irban.rekap` (`Rekap Saya`); otorisasi lewat `SptPolicy::rekap` (Pimpinan, atau Irban yang punya irban). Irban selalu dikunci ke `irban_id`-nya (nilai `irban` dari URL/klien diabaikan, juga di pembangun ekspor); tab `Per Irban | Gabungan` hanya untuk Pimpinan. Pimpinan tidak punya pilihan Irban di layar; `irban` hanya dikenali lewat URL/ekspor (nama file `-irban-{kode_nomor}`).
- Tata letak bagian dibuat satu kali di `PembangunRekap::bagian()` dan dipakai halaman, xlsx, dan PDF, sehingga angka file sama dengan layar (PRD §14 butir 6).
- Filter TW: semua tabel dipersempit ke TW itu. Rencana vs Realisasi menampilkan satu baris TW tanpa baris Total; Per Klasifikasi/Per Jenis menampilkan nilai TW itu dan baris Total TW itu. Tanpa filter: Rencana vs Realisasi = TW I–IV + Total, tabel lain = total setahun.
- Per Klasifikasi dan Per Jenis Penugasan menampilkan semua baris, termasuk yang bernilai nol dan `Tanpa jenis penugasan` bila ada.
- xlsx: `ArrayExport` hanya satu sheet, jadi tiga bagian disusun berurutan dalam satu sheet dengan baris judul bagian dan baris kepala kolom per tabel (bukan satu sheet per bagian). Tabel Rencana vs Realisasi di file: satu per irban ditambah `Gabungan` bila lebih dari satu irban. Persen kosong ditulis `–`.
- `PembangunRekap::jumlah()` selalu 0: rekap hanya tiga tabel kecil, jadi selalu diunduh langsung (tanpa antrean).
- Fixture rekap Task 1 dipindah ke trait `Tests\Feature\Rekap\RekapFixture` agar tes halaman memakai angka hitung-manual yang sama.
