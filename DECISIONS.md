# DECISIONS

- Versions: livewire/livewire v4.4.7 (installed on laravel/framework ^13.17, no conflicts), tailwindcss 4.3.3 + @tailwindcss/vite 4.3.3 (vite 8.3.4), @tailwindcss/forms 0.5.11, alpinejs/@alpinejs/intersect/focus/sort ^3.17.4, chart.js ^4.5.1. Reason: latest stable; `npm run build` passes.
- Alpine plugins: Livewire 4.4.7's `livewire.esm.js` already bundles Alpine with intersect, sort, focus (plus morph, history, resize, collapse, anchor, mask). `resources/js/app.js` therefore registers none via `Alpine.plugin` and only calls `Livewire.start()`. Reason: avoid a second Alpine instance and double registration. The npm packages `alpinejs`, `@alpinejs/*` stay installed as requested but are unused.
- Chart.js: installed only, not imported in `app.js` (no chart in Fase 0).
- `@source` lines for Pagination views and `storage/framework/views` kept from the skeleton, above `@plugin`.
- `resources/js/bootstrap.js` created as a one-line comment-only module so `public.js` stays verbatim from DESIGN §7.6 (`import "./bootstrap"`). Reason: the Laravel 13 skeleton has no bootstrap.js.
- Removed the skeleton's `fonts: [bunny('Instrument Sans')]` block and `bunny` import from `vite.config.js`. Reason: DESIGN §4 specifies Inter and Plus Jakarta Sans, self-hosted, no hot-linking. Self-hosting itself is deferred to a later phase.
- Layouts: `layouts/public.blade.php` (loads `app.css` + `public.js`, no Livewire) and `layouts/app.blade.php` (`app.css` + `app.js`, `@livewireStyles`, `@livewireScriptConfig`) are empty shells, used as `<x-layouts::public>` / `<x-layouts::app>` (Livewire's `layouts::` namespace maps to `resources/views/layouts`). Sidebar and bell deferred from PRD Fase 0 (user scoped Fase 0 to empty layouts).
- Livewire script: no `config/livewire.php` is published and none changed; `/dashboard` renders only `@livewireScriptConfig` + the Vite `app.js` module (no auto-injected `livewire.js`), so Livewire starts once.
- Scaffold was created in a temp subfolder and moved to the root; no design file was moved or overwritten.
- Backend packages from PRD §11 (maatwebsite/excel, barryvdh/laravel-dompdf, spatie/laravel-activitylog) are deferred to the phases that use them.
- DB left at the skeleton default until a phase needs it.
- Removed `welcome.blade.php` and the stock `ExampleTest` (covered by `LayoutPlaceholderTest`); `/` is the public placeholder, `/dashboard` the app placeholder, no auth.
- The skeleton's CLAUDE.md (Laravel Boost guidelines) was discarded to keep the project's own CLAUDE.md, and AGENTS.md was removed for the same reason; Boost can be installed later if wanted.

## Fase 1, Task 1
- Kolom baru `users` (`username`, `role`, `irban_id`, `wajib_ganti_password`) ditambahkan lewat migrasi baru; kolom bawaan `name`/`email`/`password` dipertahankan. `irban_id` tanpa foreign key (tabel `irban` datang di Fase 2). `role` punya default `irban` di DB.
- `/masuk` (route `login`) di Task 1 hanya stub berisi heading "Masuk" agar redirect tamu bisa dites; Task 2 menggantinya dengan login nyata.
- Route `/dashboard` Fase 0 (placeholder) diganti redirect ke dasbor per role; view `placeholder/app` dihapus. Guard ganti-kata-sandi-wajib belum ada (Task 2).
- `lang/id/` hanya berisi kunci yang dipakai Fase 1 (`auth`, `passwords`, `validation`: required, email, confirmed, min.string, unique, password.*, attributes). Kunci lain jatuh ke `en` (fallback_locale). Pesan `passwords.user` sengaja sama dengan `passwords.sent` agar tidak membocorkan keberadaan email.

## Fase 1, Task 2
- Logo (64px di panel merek, di band mobile) dihilangkan karena aset logo belum ada; panel hanya berisi teks "SIMON-SPT", subjudul dan garis accent-400. Motif Delapan Sungai digambar sebagai SVG inline dekoratif (8 garis bergelombang, mint-200, opacity 15%, `aria-hidden`).
- `blade-ui-kit/blade-heroicons` 2.7 dipasang: Packagist menunjukkan `illuminate/support ^13.0` (blade-icons 1.10 juga mendukung 13). Ikon dirender lewat helper `svg()`; SVG Heroicons sudah membawa `aria-hidden="true"`.
- Galat kredensial dan lockout disimpan di kunci error `login` (bukan `username`) agar tampil sebagai satu alert umum tanpa petunjuk per field (login.md §1). Galat validasi biasa (kolom kosong) tetap inline + ringkasan galat (DESIGN §10).
- Kartu auth memakai padding dan elevasi DESIGN §5 (`p-4 lg:p-5`, elevasi 1: `border border-neutral-200 shadow-xs`), menggantikan `p-8`/`shadow-sm` dari login.md §1, karena DESIGN.md menang atas file halaman (CLAUDE.md); diputuskan controller pada review Task 2.
- `x-ui.alert`: tidak ada token latar semantik (mis. danger-50) di §13, jadi alert memakai permukaan putih + tepi kiri 4px dan ikon berwarna (info-800, accent-700, danger-700, success-700); teks neutral-900 di atas putih. Makna ada di teks dan ikon, bukan warna.
- Tombol nonaktif memakai neutral-100 + neutral-400 persis seperti DESIGN §8 (kontrol nonaktif dikecualikan dari WCAG 1.4.3).
- Cincin fokus global `:focus-visible` (mint-600, 2px, offset 2px) ditambahkan di `app.css` (`@layer base`); input/checkbox memakai ring mint-600 milik utilitas Tailwind karena plugin forms menimpa outline.
- Salinan tambahan yang tidak ada di login.md: judul "Lupa Kata Sandi", halaman "Atur Ulang Kata Sandi" (helper "Minimal 8 karakter, huruf besar dan kecil, serta angka.", tombol "Simpan kata sandi"), label "Kekuatan:", pengumuman akhir lockout "Silakan coba masuk kembali.", teks sr-only "(terpenuhi)/(belum terpenuhi)/(diperiksa saat disimpan)", judul ringkasan "Periksa N isian berikut" (DESIGN §10), dan tombol ghost "Keluar" di halaman wajib ganti (satu-satunya jalan keluar; bukan navigasi).
- Syarat "Berbeda dari kata sandi lama" tidak bisa dicek di browser (server tidak mengirim kata sandi lama): tampil netral, berubah ke ikon gagal bila server menolak. Meter kekuatan: skor = jumlah 3 syarat + 1 bila ≥12 karakter atau ada simbol (1 Lemah … 4 Sangat kuat), heuristik sederhana.
- Atur ulang kata sandi lewat email tidak menghapus `wajib_ganti_password`; pengguna yang ditandai tetap harus melewati halaman wajib ganti.
- Aturan kata sandi didefinisikan sekali lewat `Password::defaults()` di `AppServiceProvider` dan dipakai oleh reset dan wajib ganti.
- Font belum di-self-host (tetap stack token §13).

## Fase 1, Task 3
- Login memakai `username` (design/auth/login.md), bukan kolom `email` seperti PRD §8; `email` tetap ada untuk reset kata sandi. Kolom bawaan `name` dipertahankan (tidak diganti nama Indonesia).
- Header dasbor minimal (`layouts/app.blade.php`): 64px, putih, border-b; kanan berisi avatar inisial (mint-100/mint-800), nama akun, caption role, dan tombol "Keluar" (POST `logout`). Sidebar, lonceng notifikasi, breadcrumbs, pengganti tahun, menu pengguna ("Profil", "Ubah kata sandi") dan hamburger ditunda ke fase yang membutuhkannya.
- Akun seeder hanya untuk pengembangan: kata sandi `password` untuk `admin`, `pimpinan`, `irban1`, `bagianumum`; jangan dijalankan di produksi.
- 419 (sesi/CSRF berakhir) sudah ditangani di `bootstrap/app.php` dan dites di `LoginTest::test_expired_csrf_redirects_to_login_with_message`; tidak diduplikasi.
- Setelah wajib ganti kata sandi berhasil, `remember_token` diganti baru; saat Admin menandai semua Irban (`RequireIrbanPasswordChange`), `remember_token` mereka dikosongkan, sehingga sesi "ingat saya" lama tidak lolos. Middleware `auth.session` sengaja tidak dipasang.
- Email reset kata sandi diterjemahkan lewat `lang/id.json` (kunci JSON bawaan Laravel: subjek, isi, tombol, salam, penutup, subcopy, hak cipta); kunci bahasa Inggris dipertahankan persis agar terjemahan terpakai.
- `UserSeeder` (akun dev berkata sandi `password`) langsung berhenti bila `app()->isProduction()`.

## Fase 2, Task 2
- Lonceng notifikasi dan pengganti tahun ("Tahun 2026") di header dasbor ditunda: belum ada notifikasi maupun data per tahun (PKPT/SPT). Menu pengguna ("Profil", "Ubah kata sandi") juga tetap ditunda; header kanan masih avatar + nama + caption role + "Keluar".
- Dasbor Admin hanya berisi h1 + grid "Akses cepat" yang dibangun dari definisi navigasi yang sama (`App\Support\Navigation`). Kartu kesehatan (Pengguna aktif, Pegawai, PKPT, Slide, Impor terakhir) dan daftar "Aktivitas terbaru" ditunda karena butuh data PKPT/log yang belum ada.
- Navigasi didefinisikan sekali di `App\Support\Navigation` (grup per role). Item hanya tampil bila `Route::has()`; grup tanpa item tidak menampilkan labelnya. Admin memakai grup admin.md; "Wilayah Irban" (`admin.wilayah-irban`, tidak disebut admin.md) dimasukkan ke Master Data setelah Objek Pemeriksaan. Nama route item masa depan (`admin.pengguna`, `admin.pkpt`, `admin.slide`, `admin.kontak`, `admin.impor`, `admin.log`) adalah perkiraan dan baru tampil saat route-nya dibuat.
- Teks item sidebar memakai neutral-600 (pasangan §3.4) dan hover neutral-900 di atas neutral-50, bukan neutral-700 seperti `_shared.md` §1, karena neutral-700 tidak ada di daftar §3.4 (DESIGN.md menang).
- Sidebar mobile (<1024) adalah elemen `<aside>` yang sama dengan sidebar desktop, digeser keluar layar (off-canvas dari kiri, scrim, `x-trap.noscroll`, Esc, fokus kembali ke hamburger), bukan instance `x-ui.drawer` terpisah, agar nav tidak dirender dua kali di dalam `@persist('sidebar')`. Status buka/tutup di `Alpine.store('nav')` karena hamburger berada di header di luar blok persist.
- Item aktif dirender server (`aria-current="page"` + `data-current`); setelah `wire:navigate` Livewire memperbarui `data-current` (otomatis/`wire:current`) dan `app.js` menyalinnya ke `aria-current`. Gaya aktif memakai varian `data-current:`.
- Label tombol ciut berganti "Luaskan menu" saat sidebar diciutkan (salinan tambahan). Logo belum ada: kotak "S" mint-700 + teks "SIMON-SPT" sebagai pengganti.
- Breadcrumb disembunyikan di bawah 640px (hanya hamburger + area akun di header) agar tidak ada scroll horizontal di 360px; h1 halaman tetap memberi konteks.
- Token `--color-scrim` (`rgb(8 43 35 / .55)`, DESIGN §5 elevasi 3) ditambahkan ke `@theme` agar scrim tidak memakai warna mentah di Blade. Warna progress bar `wire:navigate` diset ke mint-600 lewat `config/livewire.php` (hanya kunci `navigate`).
- `x-ui.table`: header sticky butuh kontainer gulir vertikal, jadi pada ≥1024 kontainer tabel dibatasi `max-h-[calc(100dvh-14rem)]` dan menggulir sendiri; di bawah itu tabel tumbuh normal dan hanya menggulir horizontal. Kolom pertama sticky saat menggulir ke samping. Sel angka cukup diberi `text-right` (tabel sudah `tabular-nums`); baris terpilih memakai `data-selected` pada `<tr>`.
- Varian prefix/suffix hanya ada di `x-ui.input` (slot `suffix` yang sudah ada); `x-ui.select` dan `x-ui.textarea` tidak memakai prefix/suffix karena tidak ada kebutuhan dan select sudah punya chevron bawaan.
- `x-ui.toast`: success dan info hilang sendiri setelah 5 detik; error dan warning bertahan sampai ditutup (DESIGN §8 hanya menyebut success dan error). Maksimal 3 toast. Selain event `toast`, `session()->flash('toast', [...])` sebelum redirect juga ditampilkan.
- `x-ui.switch` memakai checkbox native dengan `role="switch"` (kompatibel dengan `wire:model` dan form biasa); jempol tidak dianimasikan (form, DESIGN §7.5).
- `x-ui.modal`/`x-ui.drawer` dibuka lewat `wire:model` (x-modelable) atau event window `open-modal`/`close-modal` dengan `{name}`; panel di-teleport ke `<body>`.
- Tes endpoint update Livewire untuk pengguna wajib-ganti-kata-sandi (`default-livewire.update`) langsung hijau: middleware di grup `web` (Task 1) sudah menanganinya; tes ini mengunci perilaku itu.
- Review tugas 2: `x-ui.modal`/`x-ui.drawer` memakai `x-trap.noscroll` tanpa `.inert` agar tumpukan toast di `<body>` tetap terbaca dan bisa dijangkau saat dialog terbuka (`aria-modal="true"` tetap). Toast non-galat diumumkan lewat region `aria-live="polite"` yang selalu ada; galat tetap `role="alert"`.
- Review tugas 2: kartu tautan di dasbor tidak beranimasi (admin.md Motion); `x-ui.card` interaktif hanya berganti warna saat hover. Card-lift (shadow-sm→shadow-md + translate) hanya lewat prop `lift`, untuk halaman publik.
- Fase 2 otorisasi: satu Gate `manage-master-data` (hanya Admin, didefinisikan di `AppServiceProvider`) dipakai semua layar master data Fase 2 lewat `Gate::authorize()` di `mount()` dan di setiap aksi komponen Livewire (endpoint update Livewire tidak menjalankan middleware route halaman). Tidak ada Policy per model; ini menyimpang dari "Policy per model" di rencana, dengan persetujuan arahan tugas 3.
- Klasifikasi: lima baris tetap PRD §9.4 diisi di migrasi (bukan seeder dev) karena data referensi wajib ada di semua lingkungan, termasuk produksi dan test. Model hanya mengizinkan mass-assign aturan; tidak ada route/aksi buat atau hapus.
- Pengaturan: nilai default satu peta konstan `Settings::DEFAULTS`; `get()`/`set()` pada kunci tak dikenal melempar `InvalidArgumentException`. Cache `settings.all` dihapus saat `set()`. Aturan validasi per kunci ada di `Settings::rules()`; `penomoran.format` wajib memuat `{nomor_urut}` dan `{tahun}`; `kendala.kategori` minimal satu, tidak boleh duplikat, dan "Lainnya" wajib tetap ada (tombol hapus diganti penanda "Tetap").
- Halaman Pengaturan menaruh keduanya `penugasan.hitungan_hari` dan `penanda.batas_terlambat_hari` dalam satu kartu "Penugasan & penanda"; kartu Rekap, PKPT, Halaman publik, Unggahan, dan Kategori kendala berdiri sendiri, masing-masing dengan "Simpan perubahan".
- Impor pegawai: warna tint baris pratinjau (#FFFBEB peringatan, #FEF2F2 galat) berasal dari admin.md, bukan DESIGN §13; ditambahkan sebagai token `--color-row-warning`/`--color-row-error` di `@theme` (kelas `bg-row-*`, memakai `!` agar menang atas latar baris `x-ui.table`). Teks di atasnya selalu neutral-900 plus ikon (x-circle / exclamation-triangle); status tidak pernah hanya warna.
- Impor pegawai: yang disimpan di state Livewire hanya string sel mentah (maks. 2000 baris; lebih dari itu ditolak). Status valid/peringatan/galat dihitung ulang dari sel mentah di setiap render dan saat impor, jadi state yang dimanipulasi klien tidak melewati validasi. Berkas unggahan tidak disimpan permanen. NIP yang sudah ada = peringatan "akan diperbarui" dan di-upsert berdasarkan NIP lewat `SavePegawai`; NIP ganda dalam berkas = galat pada baris berikutnya.
- `x-ui.file-upload` menerima prop `accept` (default `.pdf`; impor memakai `.xlsx`). Pesan galat NIP memakai teks `SavePegawai` ("NIP harus 18 digit angka.") dengan awalan "Baris N:" di pratinjau, bukan teks contoh "tidak 18 digit" dari admin.md.
- Impor pegawai: sel NIP bertipe angka ditolak sebagai galat ("NIP tersimpan sebagai angka; ubah kolom NIP menjadi teks.") karena Excel hanya menyimpan sekitar 15 digit signifikan sehingga NIP 18 digit bisa berubah diam-diam. Kolom opsional yang tidak ada di header dianggap kosong; batas 2000 baris dan normalisasi tipe juga ditegakkan ulang pada state mentah dari klien.
- `x-ui.combobox` memfilter secara client-side (opsi diberikan penuh, cukup untuk ratusan pegawai) alih-alih query Livewire dengan debounce 250ms yang disebut DESIGN §8; ganti ke query Livewire bila opsi menjadi ribuan.
- Irban: policy per model belum dibuat; otorisasi memakai gate `manage-master-data` di mount dan setiap aksi, sama seperti Pegawai. `email_tembusan` yang kosong disimpan sebagai `null`; baris kosong di editor dibuang sebelum validasi.
- Hapus Irban diblokir bila dipakai pengguna atau irban_tahunan; pengecekan tim dan wilayah ditambahkan di Task 7/8 (`Irban::isReferenced`). `Pegawai::isReferenced` kini mengecek irban_anggota dan PPJ; tim_anggota menyusul di Task 7.
- Komposisi Irban Tahunan: pegawai nonaktif yang sudah tersimpan tetap boleh dipertahankan saat menyimpan ulang, tetapi tidak dapat dipilih baru.
- Migrasi FK `users.irban_id` mengosongkan nilai yatim sebelum menambah constraint. `DashboardShellTest` memakai `admin.tim` sebagai rute palsu dan `admin.slide` sebagai rute yang belum ada.
- Aturan satu irban per pegawai per tahun ditegakkan di aplikasi (skema tetap sesuai PRD §8) dengan `Cache::lock("irban-tahunan-{tahun}")` di sekitar pengecekan dan penulisan; bila kunci tidak didapat dalam 5 detik, pesannya "Data sedang diperbarui oleh pengguna lain. Coba lagi.". Deploy multi-server membutuhkan cache store bersama (database atau redis).
- Tim: PRD menang atas admin.md ("≤1 Supervisor/Dalnis"): komposisi tepat satu Supervisor/Dalnis dan tepat satu Ketua, anggota bebas, tiap pegawai paling banyak sekali per tim (`ValidateTimComposition`, dipanggil `SaveTim`). Anggota tim boleh pegawai aktif mana pun (tidak dibatasi anggota Irban tahunan); anggota nonaktif yang sudah tersimpan tetap dipertahankan. Urutan 1..n mengikuti urutan tampilan; pengurutan lewat tombol Naikkan/Turunkan tanpa seret.
- Tim: otorisasi memakai gate `manage-master-data` (seperti halaman master data lain), bukan Policy tersendiri; tahun dibatasi tahun ini -2 sampai +1 di `SaveTim`.
- Objek/Wilayah: nama pada `ObjekSeeder` (5 kecamatan Muara Enim, 9 dinas/badan umum, BUMD Perumdam Lematang Enim, beberapa desa/sekolah/puskesmas) hanyalah contoh; tabel wilayah Irban I yang resmi harus menggantikannya sebelum dipakai. Seeder hanya jalan di non-produksi.
- Objek/Wilayah: otorisasi lewat gate `manage-master-data` (tanpa Policy per model, seperti Tim). `x-ui.combobox` belum mendukung item nonaktif, jadi objek yang sudah dipegang Irban lain dikeluarkan dari pilihan kartu lain dan dicantumkan di bagian "objek tidak tersedia" dengan label "(Irban II)". Anak kecamatan diurutkan per jenis lalu nama dan jenisnya tampil di kolom Jenis (tanpa baris judul kelompok). Aturan satu-Irban-per-objek-per-tahun memakai `Cache::lock("irban-wilayah-{tahun}")` plus unique DB.
- Objek: jenis objek yang sudah ada di `irban_wilayah` tidak boleh diubah ke jenis di luar kecamatan/dinas_badan/bumd/rsud; pesan: "Objek yang sudah ditugaskan ke Irban tidak dapat diubah ke jenis yang tidak bisa ditugaskan." Pohon kecamatan memakai pola ARIA treegrid mode fokus-baris (roving tabindex; panah, Home/End, Kanan/Kiri expand/collapse, Enter = Ubah). Pencarian: kecamatan yang cocok menampilkan semua anaknya; bila hanya anak yang cocok, hanya anak itu yang tampil.
