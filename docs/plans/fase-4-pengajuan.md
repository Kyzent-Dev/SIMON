- Numbering (`App\Services\Penomoran`, PRD §9.1):
  - Counter key: `tahun` = decision year (Asia/Jakarta) when `penomoran.reset_tahunan`, else 0; `scope` = `global` or `irban:{id}`.
  - `ambil(Irban $irban, CarbonImmutable $tanggal): array{counter: NomorCounter, nomor_urut: int, nomor_lengkap: string}` must be called inside the caller's `DB::transaction`; it creates the counter row if missing (`firstOrCreate` guarded against the unique race), then reads it with `lockForUpdate()` and increments `nomor_terakhir` by exactly 1. Never `MAX(nomor_urut)+1`. On SQLite the transaction must take the write lock before reading (e.g. issue the increment `UPDATE` first, then read the row; or `IMMEDIATE` transactions) and the connection needs a `busy_timeout`, so concurrent processes wait instead of failing.
  - `pratinjau(Irban, CarbonImmutable)` = the number the next `ambil` would produce, without locking or writing.
  - `format(...)`: template `penomoran.format` with placeholders `{kode_arsip}` (`penomoran.kode_arsip`), `{nomor_urut}` (plain integer, no padding), `{kode_irban}` (`irban.kode_nomor`), `{tahun}` (decision year, even when not resetting), `{klasifikasi}` (klasifikasi `nama` uppercased with spaces → `-` when `penomoran.klasifikasi_di_nomor`, else the placeholder and one adjacent `/` are removed). Example default: `700/752/INSPEKTORAT-II/SPT/2026`.
  - Numbers are never changed or reused; cancelling only changes `status_pengajuan`; counters never decrement.
  - `AturNomorAwal(User, int $tahun, ?Irban, int $nomor)`: sets `nomor_terakhir` for that counter key (the "nomor terakhir dari stambook fisik", PRD §7.7); only while no SPT has a number on that counter (`Nomor awal hanya bisa diatur sebelum ada nomor yang terbit pada register ini.`); `nomor` integer ≥ 0; who/when stored on the counter row (`diatur_oleh`, `diatur_pada`).
- Status (`App\Enums\StatusSpt`, labels exactly DESIGN §3.6: `Draf`, `Menunggu Nomor`, `Perlu Revisi`, `Ditolak`, `Siap Dilaksanakan`, `Pelaksanaan`, `Penyusunan Laporan`, `Selesai`, `Dibatalkan`; icons per §3.6). `Spt::status()` computes from `status_pengajuan` and today (Asia/Jakarta) per PRD §9.2: `diterima` → `Siap Dilaksanakan` if today < `tanggal_mulai`, `Pelaksanaan` if within, `Penyusunan Laporan` if after `tanggal_selesai`. `Selesai` is not reachable until Fase 5 (leave a clear extension point; no LHP logic now). No cron.
- Duration: inclusive days between `tanggal_mulai` and `tanggal_selesai`; when `penugasan.hitungan_hari` = `kerja`, count Monday–Friday only (no holiday calendar — record). Text "Durasi: N hari".
- Personel rules (`App\Actions\Spt\ValidatePersonel`, used by submit and every save path that requires completeness): at least one personel (`Pilih minimal satu personel.`); exactly one `ketua` (`Tetapkan tepat satu Ketua Tim`); at most one `supervisor_dalnis` (`Maksimal satu Supervisor/Dalnis.`); no duplicate pegawai (`:nama tercantum lebih dari sekali.`); only active pegawai may be newly added. Labels in the form: "Supervisor/Dalnis", "Ketua Tim", "Anggota". `urutan` 1..n in display order; `sumber` = `tim` (with `tim_id`) or `tambahan`.
- Submission rules (`App\Actions\Spt\SimpanSpt` with mode `draf` | `ajukan`):
  - Draf requires only `diinput_oleh` (valid PPJ/anggota of the irban this year, as Fase 3 `DiinputOleh`) and `klasifikasi`; everything else may be incomplete.
  - Ajukan requires: klasifikasi; `pkpt_item_id` when the klasifikasi has `wajib_item_pkpt` (`Pilih item PKPT untuk SPT Reguler.`), unless "Non-PKPT" is checked — Non-PKPT is allowed only when the klasifikasi does not require an item; the item must belong to the same irban; jenis penugasan (taken from the item when one is chosen; otherwise required manually); ≥1 objek; `periode_diperiksa` required max 255; `uraian_untuk` required max 1000; dates required, `tanggal_mulai` ≤ `tanggal_selesai`; PPJ required (active pegawai); personel rules; lampiran optional PDF ≤ 5 MB (PRD §7.6; message `Lampiran harus PDF dan maksimal 5 MB.`); catatan optional max 1000.
  - PKPT Draf (PRD §7.5): if the chosen item's PKPT is Draf → warning `PKPT belum disahkan.`; if `pkpt.draf_memblokir` = true, ajukan is rejected with the same message.
  - Out-of-PKPT warning (irban.md): when an item is chosen and `KesesuaianPkpt::sesuai(item, mulai, selesai)` is false → `Di luar jadwal PKPT ({rentang berlaku}). SPT akan ditandai Tidak Sesuai PKPT.` Warns, never blocks.
  - Allowed transitions for Irban: create → `draf`; `draf`/`perlu_revisi` → save stays, ajukan → `menunggu_nomor` (sets `diajukan_pada`); any other status → `SPT ini sudah dikirim dan tidak dapat diubah.` Each save/ajukan writes `spt_riwayat` with `diinput_oleh`.
  - Uraian suggestion (`App\Services\SaranUraian`): `Melaksanakan {jenis} pada {objek}` + (periode ? ` untuk {periode}` : ``) + `.` where `{objek}` joins names with `, ` and ` dan ` before the last (e.g. `Melaksanakan Reviu LKjIP pada Dinas PUPR, Dinas Kesehatan dan Dinas Pendidikan untuk Tahun Anggaran 2025.`). "Gunakan saran" restores it.
  - Option sources: PKPT items = the irban's items in the PKPT of the current year (any PKPT status); teams = the irban's `tim` for the current year; PPJ default = `irban_tahunan.ppj_pegawai_id` of the current year; objek = all `objek` shown as "Kecamatan › Desa" for children.
- Bagian Umum decisions (`app/Actions/Spt`), each inside a transaction that re-reads the SPT with `lockForUpdate` and requires `status_pengajuan` = `menunggu_nomor`, else `Pengajuan ini sudah diproses oleh pengguna lain.`:
  - `TerimaPengajuan(User, Spt)`: decision date = today (Asia/Jakarta); `Penomoran::ambil`; sets `nomor_urut`, `nomor_lengkap`, `nomor_counter_id`, `tahun`, `tanggal_spt`, status `diterima`; riwayat `diterima`.
  - `MintaRevisi(User, Spt, string $catatan)` / `TolakPengajuan(User, Spt, string $catatan)`: catatan required, min 10, max 1000 (`Catatan minimal 10 karakter.`); status `perlu_revisi` / `ditolak`; riwayat with `alasan`.
  - `CatatNomorManual(User, array)`: irban, klasifikasi, jenis penugasan (optional), `uraian_untuk` (perihal, required), `tanggal_mulai`/`tanggal_selesai` required, `alasan` required min 10; creates an SPT `sumber` = `manual`, status `diterima`, number from the same `Penomoran::ambil` sequence (PRD §7.7 wins over bagian-umum.md's typed number field — record). Personel optional.
  - `BatalkanNomor(User, Spt, string $alasan)`: only `diterima` SPT (`Hanya nomor yang sudah terbit yang dapat dibatalkan.`); `alasan` required min 10 (`Alasan pembatalan minimal 10 karakter.`); status `dibatalkan`; number and counter untouched.
- Register: per year (`tahun` of the number) all numbered SPT (`diterima`, `dibatalkan`, and later statuses) ordered by `nomor_urut` (then irban when scope is per irban); columns No. Urut, Nomor SPT, Tanggal (tanggal_spt), Irban, Perihal/Jenis (jenis penugasan name or uraian truncated), Status (`x-app.status-badge`), Keterangan (sumber Manual/Impor + cancel reason); search by number; filters status, irban, month; 100 per page; export Excel (`ArrayExport`) and PDF (`barryvdh/laravel-dompdf`, check Laravel 13 compatibility on Packagist; if incompatible pick an equivalent and record) following active filters, synchronous.
