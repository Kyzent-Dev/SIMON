## Exact values
- Migration (new file, do not edit earlier migrations): Laravel's `notifications` table (`php artisan make:notifications-table`, keep its standard columns: uuid `id`, `type`, morphs `notifiable`, `data` text, `read_at` nullable timestamp, timestamps). Plus, in a second new migration, on `spt`: `terlambat_diberitahu_pada` timestamp nullable, `pengingat_final_pada` timestamp nullable (idempotency of the daily command).
- Queueing (PRD §7.10 "Email dikirim lewat antrean"): every notification class `implements ShouldQueue`, uses `Queueable`, `afterCommit`, and `viaConnections()` returns `['database' => 'sync', 'mail' => config('queue.default')]` so the bell entry is written immediately and the email goes through the `database` queue. `via()` returns `['database', 'mail']`, except: mail is skipped when `routeNotificationForMail()` yields no address.
- Base class `App\Notifications\NotifikasiSimon` (abstract). Subclasses implement `jenis(): string`, `judul(): string`, `konteks(): ?string`, `url(): string`, `isi(): array` (lines of email body) and optionally `catatan(): ?string`. The base provides:
  - `toArray()` = `['jenis' => …, 'judul' => …, 'konteks' => …, 'url' => …, 'catatan' => …]` (the bell and list page read only these keys; `url` is a relative path from `route(..., absolute: false)`).
  - `toMail()` = `MailMessage` with subject `"[SIMON-SPT] {subjek}"` where `subjek()` defaults to `judul()`, greeting none, the `isi()` lines, the `catatan` as a quoted line `Catatan: …` when present, action button `Buka SPT` for SPT-related jenis else `Buka SIMON-SPT`, pointing at `url($this->url())`; the theme from Exact values "Email".
- `jenis` keys and icon tiles (heroicons outline, tile per §3.4 pairs): `pengajuan_baru` (`inbox-arrow-down`, info), `pengajuan_diterima` (`check-circle`, success), `pengajuan_perlu_revisi` (`pencil-square`, warning), `pengajuan_ditolak` (`x-circle`, danger), `nomor_dibatalkan` (`no-symbol`, danger), `revisi_jadwal_diajukan` (`calendar-days`, info), `revisi_jadwal_disetujui` (`calendar-days`, success), `revisi_jadwal_ditolak` (`calendar-days`, danger), `spt_terlambat` (`clock`, danger), `pengingat_spt_final` (`document-arrow-up`, warning), `ringkasan_mingguan` (`chart-bar`, neutral). Unknown jenis → `bell`, neutral. The mapping lives in one place (`App\Support\JenisNotifikasi::ikon(string): array{ikon: string, nada: string}`) used by bell and list page.
- Recipients — `App\Services\PenerimaNotifikasi` (Collection of `User`):
  - `bagianUmum()`: all users with role `bagian_umum`.
  - `pimpinan()`: all users with role `pimpinan`.
  - `irban(int $irbanId)`: all users with role `irban` and that `irban_id`.
  - Mail routing: `User::routeNotificationForMail()` — for role `irban`: `[$irban->email_notifikasi ?: $user->email, ...$irban->email_tembusan ?? []]` (unique, empty values dropped; PRD §5); other roles: `$user->email` (null/empty → no mail).
- Events (class `App\Notifications\…`, trigger, recipients, `jenis`, `judul`, `konteks`, `url`, `catatan`):
  - `PengajuanBaru` — `SimpanSpt` when the SPT transitions to `menunggu_nomor` (first submit and every resubmit after Perlu Revisi; not on draft saves or edits that stay `menunggu_nomor`) → `bagianUmum()`; `pengajuan_baru`; judul `Pengajuan nomor SPT baru dari {irban->nama}`; konteks `{jenis penugasan nama} · {untuk, Str::limit 60}`; url `route('bagian-umum.pengajuan', ['pilih' => $spt->id])`; no catatan.
  - `PengajuanDiputuskan` (one class, jenis from status) — `TerimaPengajuan` / `MintaRevisi` / `TolakPengajuan` (via the `PutuskanPengajuan` trait, after the transaction) → `irban($spt->irban_id)`; jenis `pengajuan_diterima` / `pengajuan_perlu_revisi` / `pengajuan_ditolak`; judul `Nomor SPT terbit` / `Pengajuan nomor SPT perlu direvisi` / `Pengajuan nomor SPT ditolak`; konteks diterima → `SPT {nomor_lengkap}`, others → `{jenis penugasan nama} · {untuk, limit 60}`; url `route('spt.show', $spt)`; catatan = the Bagian Umum catatan (perlu revisi / ditolak). Email subjects therefore: `[SIMON-SPT] Nomor SPT terbit`, `[SIMON-SPT] Pengajuan nomor SPT perlu direvisi` (matches `_shared.md` §2), `[SIMON-SPT] Pengajuan nomor SPT ditolak`; the diterima email body includes `Nomor SPT: {nomor_lengkap}`.
  - `NomorDibatalkan` — `BatalkanNomor` → `irban($spt->irban_id)`; `nomor_dibatalkan`; judul `Nomor SPT dibatalkan`; konteks `SPT {nomor_lengkap}`; url `spt.show`; catatan = alasan.
  - `RevisiJadwalDiajukan` — `AjukanRevisiJadwal` → `pimpinan()`; `revisi_jadwal_diajukan`; judul `Revisi jadwal PKPT diajukan oleh {irban->nama}`; konteks `{jenis penugasan nama} · {rentang lama} → {rentang baru}` (rentang as `d F Y – d F Y` via existing helpers); url `route('pimpinan.revisi-jadwal')`; catatan = alasan.
  - `RevisiJadwalDiputuskan` — `PutuskanRevisiJadwal` → `irban($item->irban_id)`; `revisi_jadwal_disetujui` / `revisi_jadwal_ditolak`; judul `Revisi jadwal PKPT disetujui` / `Revisi jadwal PKPT ditolak`; konteks `{jenis penugasan nama} · {rentang baru}`; url `route('irban.pkpt')`; catatan = komentar (when present).
  - `SptTerlambat` — daily command → `irban($spt->irban_id)`; `spt_terlambat`; judul `SPT terlambat diselesaikan`; konteks `SPT {nomor_lengkap}`; email body `Penyusunan laporan sudah lebih dari {N} hari sejak tanggal selesai {d F Y}.` (N = `penanda.batas_terlambat_hari`); url `spt.show`.
  - `PengingatSptFinal` — daily command → `irban($spt->irban_id)`; `pengingat_spt_final`; judul `Pengingat: SPT final belum diunggah`; konteks `SPT {nomor_lengkap}`; body `Penugasan dimulai {d F Y}. Unggah SPT final bertanda tangan di halaman detail SPT.`; url `spt.show`.
  - `RingkasanMingguan` — weekly command → `pimpinan()`; `ringkasan_mingguan`; judul `Ringkasan mingguan SIMON-SPT`; konteks `{senin lalu d F Y} – {minggu kemarin d F Y}`; url `route('pimpinan.dashboard')`; email body lines (counts over the previous Monday 00.00–Sunday 23.59 WIB, plus current snapshot): `Nomor SPT terbit: {n}` (riwayat `diterima` + `dicatat_manual` in the window), `SPT ditandai Selesai: {n}` (riwayat `ditandai_selesai` in the window), `Pengajuan menunggu nomor: {n}` (now), `Revisi jadwal menunggu persetujuan: {n}` (now), `SPT terlambat: {n}` (now, via `PenandaSpt`), followed by up to 10 lines `{nomor_lengkap} · {irban nama} · {hari} hari sejak tanggal selesai` for the terlambat SPT (oldest first) and `dan {k} lainnya.` when more. The counting lives in a service method `App\Services\RingkasanMingguan::hitung(CarbonImmutable $senin): array` (tested directly), not in the notification.
