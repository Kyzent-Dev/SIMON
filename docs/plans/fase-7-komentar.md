- Known pitfalls (from `docs/plans/serah-terima.md`, each cost a fix round before):
  - **Focus after action:** when a modal/form closes and its trigger disappears or becomes disabled, move focus to a stable target (heading or `tabindex="-1"` element) via an event dispatched from the component; never let focus fall to `body`.
  - **`sr-only` inside scroll containers:** wrappers holding `sr-only` spans inside `overflow-x-auto` must be `relative`, or the page widens at 360px. Check `document.documentElement.scrollWidth <= 360` with the reply form open.
  - **"Diinput oleh"** always in the form/modal footer (login.md §5), never in the body.
  - **Business rules are not recomputed in components**: the action/service exposes a non-throwing method used by both UI and validation (e.g. `ValidatePersonel::cek()`, `TandaiSelesai::bisa()`); here `TutupPermintaan::bisa()`.
  - **Non-field errors:** `ValidationException` keys with no field in the form are shown as a toast, never silently dropped.
  - **Id lookups always scoped** (here: comments through the SPT), including preview methods, not just save actions.
  - **Timezone:** date/time columns are stored in Jakarta time (APP_TIMEZONE); never `->utc()` when comparing.
  - **xlsx export:** use `App\Exports\ArrayExport`; no new exporter without that binder.
  - **Carbon:** `parse('')` returns "now"; reject empty values before parsing.
  - **Livewire:** a method name must not equal a public property name; ids the client must not change get `#[Locked]`; authorize in `mount()` and every action (the update endpoint skips route middleware).
  - **Factories with `unique()` years** can collide with explicit years in tests; use a range outside the years the test writes.
  - **Numbering:** `Penomoran::ambil` only inside `DB::transaction(..., attempts: 3)` and always with the klasifikasi.
  - **Sticky elements on the dashboard:** the header is sticky 64px (`z-30`); any new `sticky top-*` against the page needs offset ≥ `top-16`.
  - **Git staging:** stage files one by one; never `.claude/`, `.playwright/`, `graphify-out/`, `.superpowers/`.
  - **Deferred from earlier phases:** when this phase delivers something earlier phases deferred "to Fase 7" (the Komentar section), find and update the leftover deferral comments (`grep -rn "Fase 7\|Komentar and Log" app/ resources/ decisions/`), e.g. the header comment of `resources/views/livewire/spt/detail.blade.php` ("Komentar and Log Aktivitas are later phases").
  - **Stale tab:** an action rejected because the state changed elsewhere (permintaan already closed) is a toast through the action's error key, not a 403, and focus moves to a stable target.
  - **Livewire upload messages:** n/a (no file fields).
  - **Notifications:** sent from the action after the transaction; recipients only from `PenerimaNotifikasi`; context strings built from optional parts with `filter()->implode(' · ')`.
  - **Alpine `$refs` after a Livewire request:** when the trigger is removed by the morph, take the focus target reference before `$wire.aksi()` (`const h = $refs.x; $wire.aksi().then(() => h.focus())`).
  - **Mobile order on the SPT detail page:** the page uses CSS `order-*` below 1024px, so DOM order differs from visual order; the Komentar section must come last both in DOM (inside the left column, after Dokumen) and visually (`order-6`), so the tab order stays sensible.

## Exact values
- Migration (new file `2026_10_23_000014_create_komentar_table.php`; do not edit earlier migrations), table `komentar`:
  - `id`; `spt_id` foreignId → `spt` cascadeOnDelete; `parent_id` nullable foreignId → `komentar` cascadeOnDelete; `user_id` foreignId → `users`; `diinput_oleh` nullable foreignId → `pegawai` (Irban authors only); `isi` text; `minta_penjelasan` boolean default false; `status_permintaan` string(10) nullable (`terbuka` / `selesai`, only on a root with `minta_penjelasan`); `ditutup_oleh` nullable foreignId → `users`; `ditutup_pada` nullable timestamp; timestamps. Index `(spt_id, parent_id)` and `(minta_penjelasan, status_permintaan)`.
- Model `App\Models\Komentar` (`protected $table = 'komentar'`), casts `minta_penjelasan` bool, `status_permintaan` → enum `App\Enums\StatusPermintaan` (`Terbuka = 'terbuka'`, `Selesai = 'selesai'`, `label()` → `Terbuka` / `Selesai`), `ditutup_pada` datetime. Relations `spt`, `parent`, `balasan` (hasMany children, oldest first), `penulis` (belongsTo User via `user_id`), `diinputOleh` (Pegawai), `ditutupOleh` (User). Scope `permintaanTerbuka()` = roots with `minta_penjelasan = true` and `status_permintaan = terbuka` (Fase 8 counts it per pimpinan dashboard and per irban via `whereHas('spt', irban_id)`; test it here). `Spt::komentar()` hasMany. Factory `KomentarFactory`.
- Threading: one level. A root has `parent_id = null`; every reply points to the root. A reply to a reply is not possible in the UI; the action rejects a `parent_id` that is not a root of the same SPT (`ValidationException` key `komentar`: `Komentar yang dibalas tidak ditemukan.`).
- `SptPolicy` new abilities (all also require `view`):
  - `komentari(User, Spt)`: role `pimpinan` — start a new root comment (with or without Minta Penjelasan).
  - `balasKomentar(User, Spt)`: role `pimpinan`, `bagian_umum`, or the owning Irban (`milik`) — reply in an existing thread.
  - `tutupPermintaan(User, Spt)`: role `pimpinan` (any pimpinan, not only the requester — Inspektur and Sekretaris share oversight; record it).
  - Admin: view only (no ability above). Comments are allowed in every SPT status the user can view (including Selesai, Ditolak, nomor dibatalkan): they never change SPT data; record it.
- Actions (`app/Actions/Komentar/`), each `handle(User $user, Spt $spt, array $data)`:
  - `TulisKomentar` — `komentari`; `$data = ['isi', 'minta_penjelasan']`; creates a root; `status_permintaan = terbuka` when `minta_penjelasan`, else null. Sends notifications (below). Returns `Komentar`.
  - `BalasKomentar` — `balasKomentar`; `$data = ['parent_id', 'isi', 'diinput_oleh']`; Irban authors must pass "Diinput oleh" validated by `App\Support\DiinputOleh::galat()` (key `diinput_oleh`), then `DiinputOleh::ingat()` after success; other roles store `diinput_oleh = null` (ignore the input). Replies are allowed on a closed permintaan (record it). Sends notifications.
  - `TutupPermintaan` — `tutupPermintaan`; `$data = ['komentar_id']`; inside `DB::transaction` re-read the root with `lockForUpdate()`; sets `status_permintaan = selesai`, `ditutup_oleh`, `ditutup_pada = now()`. Non-throwing `bisa(Komentar $root): ?string` returns the blocking message or null, used by both the UI (to show/hide the button and the caption) and `handle()` (throws it under key `komentar`):
    - not a Minta Penjelasan root → `Komentar ini bukan permintaan penjelasan.`
    - already `selesai` → `Permintaan penjelasan sudah ditutup.`
    - no reply from a user with role `irban` yet → `Permintaan baru dapat ditutup setelah Irban membalas.` (PRD §6.3 "tetap terbuka sampai Irban membalas dan pimpinan menutupnya").
  - Validation of `isi` (shared by both write actions): trimmed; empty → key `isi` `Tulis isi komentar.`; > 2000 chars → `Komentar maksimal 2000 karakter.`; `minta_penjelasan` read with `filter_var(..., FILTER_VALIDATE_BOOLEAN)`. Comment text is stored and rendered as plain text (escaped, newlines kept with `whitespace-pre-line`), never as Markdown or HTML.
- Notifications (`App\Notifications\…`, extend `NotifikasiSimon`; add the three jenis to `NotifikasiSimon::JENIS_SPT` so the email CTA reads `Buka SPT`; icons in `App\Support\JenisNotifikasi::IKON`):
  - `KomentarBaru` — jenis `komentar_baru` (`chat-bubble-left-ellipsis`, info) or `minta_penjelasan` (`question-mark-circle`, warning) when the root is a Minta Penjelasan **and** the comment is that root; judul `Komentar baru dari {penulis->name}` / `{penulis->name} meminta penjelasan`; for a reply judul `Balasan komentar dari {penulis->name}` (jenis `komentar_baru`).
  - `BalasanPenjelasan` — jenis `balasan_penjelasan` (`chat-bubble-left-right`, success); judul `Balasan atas permintaan penjelasan dari {penulis->name}`.
  - All three: konteks = `SPT {nomor_lengkap}` when the SPT has a number, else `{jenis penugasan nama} · {untuk, Str::limit 60}` via `filter()->implode(' · ')`; url = `route('spt.show', $spt, absolute: false).'#komentar-'.$root->id`; catatan = `Str::limit($komentar->isi, 200)`; email `isi()` = one line `{penulis->name} menulis di SPT {nomor or "tanpa nomor"}:` (the catatan line carries the text).
  - Recipients — new `PenerimaNotifikasi::utasKomentar(Komentar $komentar): Collection`: the users of the SPT's irban (`irban($spt->irban_id)`) ∪ the authors of the root and of every reply in that thread, minus the author of `$komentar`, unique by id.
  - Routing in the actions: a root → `KomentarBaru` to `utasKomentar`. A reply → if the root is a Minta Penjelasan whose author is not the reply author: `BalasanPenjelasan` to the root author (the peminta) and `KomentarBaru` to `utasKomentar` minus the peminta; otherwise `KomentarBaru` to `utasKomentar`. Closing a permintaan sends nothing (record it).
- Komentar section on the SPT detail page (Livewire child `App\Livewire\Spt\Komentar`, view `livewire/spt/komentar.blade.php`, mounted in `livewire/spt/detail.blade.php` inside the left column after Dokumen, wrapper `order-6 lg:order-none`; it reloads its own data, never the parent's):
  - Card with `<h2 id="judul-komentar" tabindex="-1">Komentar</h2>` and, when > 0, a caption `{n} komentar` (roots + replies). Threads oldest first, replies oldest first, indented under their root (left rule `border-l-2 border-neutral-200 pl-4` on ≥640; on 360 indent 12px).
  - Each comment (`<article id="komentar-{id}" aria-labelledby=…>`): author line `{penulis->name}` 14/600 + role caption (`Role::label()`), for Irban authors a second caption `Diinput oleh {pegawai nama_bergelar}` (login.md §5 audit display); time = relative with `<time datetime>` and `title` = absolute `d F Y H.i WIB`; body 14px `neutral-900`, `whitespace-pre-line break-words`.
  - Minta Penjelasan root: card treatment like `x-ui.alert` warning (white surface, `border-l-4 border-l-accent-700`, icon `question-mark-circle` `text-accent-700`) when Terbuka; `border-l-success-700` + `check-circle` `text-success-700` when Selesai; label text `Permintaan Penjelasan · Terbuka` / `Permintaan Penjelasan · Selesai` (neutral-900, 12/600) — icon + label, never color alone. Under it: Terbuka without an Irban reply → caption `Menunggu balasan Irban`; Selesai → caption `Ditutup oleh {ditutupOleh->name} · {d F Y H.i} WIB`.
  - Pimpinan on a Terbuka root where `TutupPermintaan::bisa()` is null: secondary button `Tutup permintaan` (accessible name `Tutup permintaan penjelasan dari {penulis->name}`), no confirmation dialog (record it). After success focus moves to the root's label element (`tabindex="-1"`), since the button disappears.
  - `Balas` ghost button per thread (users with `balasKomentar`), accessible name `Balas komentar {root penulis->name}`, `aria-expanded`; opens one inline reply form under that thread (opening another closes the first). Reply form: `x-ui.textarea` label `Balasan`, counter `{n}/2000`, footer: (Irban only) `x-app.diinput-oleh` on the left, `Batal` (secondary) + `Kirim balasan` (primary) on the right. Focus moves into the textarea on open; on `Batal` or success it returns to the thread's `Balas` button.

Permintaan tetap terbuka sampai ditutup pimpinan.`, primary button `Kirim komentar`. After success the textarea clears, the switch resets, and focus moves to the new comment's `<article>` (`tabindex="-1"`).
  - Empty state: `Belum ada komentar.` (plain caption, neutral-600, inside the card; no illustration).
  - Toasts: `Komentar dikirim`, `Balasan dikirim`, `Permintaan penjelasan ditutup`. Field errors inline (`isi`, `diinput_oleh`); any other key (`komentar`, `spt`) → error toast and focus to `judul-komentar`.
  - Users without `komentari` / `balasKomentar` (Admin) see the threads only.
